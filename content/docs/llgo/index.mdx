LLGo compiles Go source to native code with LLVM. It has its own compiler driver and runtime. You can start with an ordinary Go module, call a library through its C application binary interface (ABI), or build the same package for a different host.

Start with the [installation guide](/docs/llgo/getting-started/installation), then compile a Go package in [your first LLGo program](/docs/llgo/getting-started/first-program).

## What LLGo provides

- LLVM code generation for native, WebAssembly, and selected embedded targets.
- A native runtime with conservative BDWGC on hosted platforms and a TinyGo-derived collector on bare-metal targets.
- Direct C and C++ ABI calls through `go:linkname`, without a cgo stack transition for ordinary linked calls.
- Python bindings through the `github.com/goplus/lib/py` packages and the llpyg binding layer.
- A Go-compatible package workflow with an explicit compatibility contract for commands and flags.

The standard Go library is supported on the documented native platforms. Other targets can have different operating-system services and runtime limits. Read [target support](/docs/llgo/reference/targets) before choosing a deployment profile.

## Version and runtime model

The stable tutorial pages in this section use LLGo `v1.0.10` and Go 1.27. LLGo's source compatibility target starts at Go 1.20, while the compiler runtime and command surface are versioned independently from the Go toolchain.

Native goroutines map one-to-one to operating-system threads and use native stacks. The default native collector is BDWGC. Build with the `nogc` tag only when the program and its libraries satisfy the resulting memory-management contract.
