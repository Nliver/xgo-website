LLGo 使用 LLVM 将 Go 源码编译为机器码，拥有独立的编译器驱动和运行时。你可以从普通的 Go 模块起步，通过 C 应用二进制接口（ABI）调用现有库，也可以为另一种宿主环境构建同一个包。

先按[安装指南](/zh-CN/docs/llgo/getting-started/installation)配置工具链，再跟着[用 LLGo 编译第一个 Go 程序](/zh-CN/docs/llgo/getting-started/first-program)编译并运行一个 Go 包。

## LLGo 提供的能力

- 使用 LLVM 为本机平台、WebAssembly 和部分嵌入式目标生成代码。
- 在有宿主操作系统的平台上使用 BDWGC 进行保守式垃圾回收，在裸机目标上使用源自 TinyGo 的垃圾回收器。
- 通过 `go:linkname` 按 C 或 C++ ABI 直接调用函数。普通的链接调用无需经过 cgo 的栈切换。
- 通过 `github.com/goplus/lib/py` 系列包和 llpyg 绑定层调用 Python。
- 沿用 Go 按包组织项目的工作方式，并明确规定各命令和参数的兼容范围。

文档列出的本机平台支持 Go 标准库。其他目标可用的操作系统服务和运行时能力可能不同。选择部署环境前，可先查阅[目标平台支持情况](/zh-CN/docs/llgo/reference/targets)。

## 版本与运行时模型

本节面向稳定版的教程使用 LLGo `v1.0.10` 和 Go 1.27。LLGo 的源码兼容目标从 Go 1.20 起算。编译器运行时和命令行接口有各自的版本，独立于 Go 工具链。

在本机平台，每个 goroutine 对应一个操作系统线程，使用原生线程栈。默认垃圾回收器为 BDWGC。只有在程序及其依赖库都能满足关闭垃圾回收后的内存管理要求时，才应使用 `nogc` 构建标签。
