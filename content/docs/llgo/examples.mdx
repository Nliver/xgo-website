description: "Use LLGo to run XGo examples that call C, C++, and Python libraries."
---

Install LLGo and place `llgo` on your command path. Run each command from its listed directory in the XGo checkout. Python demos need the Python runtime that LLGo is configured to use. See [LLGo first compilation](/docs/llgo) for setup and the [LLGo interoperability guide](/docs/llgo/interoperability) for native and Python imports.

The shared module pins `github.com/goplus/lib v0.2.0`. Generate Go source with `xgo go .`, then run that package with `llgo run .`. LLGo v1.0.10 rejects the linker flags that this XGo revision passes when invoked through `XGO_GOCMD=llgo xgo run .`.

## Format a custom error

Run from `demo/_llgo/errors`.

Implement Go’s `error` interface and pass the formatted error to C.

### errors.xgo

```xgo
import (
	"c"
)

// New returns an error that formats as the given text.
// Each call to New returns a distinct error value even if the text is identical.
func New(text string) error {
	return &errorString{text}
}

// errorString is a trivial implementation of error.
type errorString struct {
	s string
}

func (e *errorString) Error() string {
	return e.s
}

e := new("an error")
c.printf c.allocaCStr(e.error+"\n")
```

```sh
xgo go .
llgo run .
```

## Run an SQLite query

Run from `demo/_llgo/sqlitedemo`.

Install SQLite for the LLGo target. Run this in a scratch directory because the example removes and recreates `test.db` in its working directory.

### sqlitedemo.xgo

```xgo
import (
	"c"
	"c/os"
	"c/sqlite"
)

func check(err sqlite.Errno, db *sqlite.Sqlite3, at string) {
	if err != sqlite.OK {
		c.printf c"==> %s Error: (%d) %s\n", c.allocaCStr(at), err, db.errmsg
		c.exit 1
	}
}

func checkDone(err sqlite.Errno, db *sqlite.Sqlite3, at string) {
	if err != sqlite.Done {
		check err, db, at
	}
}

os.remove c"test.db"

db, err := sqlite.open(c"test.db")
check err, db, "sqlite: Open"

err = db.exec(c"CREATE TABLE users (id INTEGER PRIMARY KEY, name TEXT)", nil, nil, nil)
check err, db, "sqlite: Exec CREATE TABLE"

stmt, err := db.prepareV3("INSERT INTO users (id, name) VALUES (?, ?)", 0, nil)
check err, db, "sqlite: PrepareV3 INSERT"

stmt.bindInt 1, 100
stmt.bindText 2, c"Hello World", -1, nil

err = stmt.step
checkDone err, db, "sqlite: Step INSERT 1"

stmt.reset
stmt.bindInt 1, 200
stmt.bindText 2, c"This is llgo", -1, nil

err = stmt.step
checkDone err, db, "sqlite: Step INSERT 2"

stmt.close

stmt, err = db.prepareV3("SELECT * FROM users", 0, nil)
check err, db, "sqlite: PrepareV3 SELECT"

for {
	if err = stmt.step; err != sqlite.HasRow {
		break
	}
	c.printf c"==> id=%d, name=%s\n", stmt.columnInt(0), stmt.columnText(1)
}
checkDone err, db, "sqlite: Step done"

stmt.close
db.close
```

```sh
xgo go .
llgo run .
```

## Open a native raylib window

Run from `demo/_llgo/tetris` with a graphical display and a raylib installation for the LLGo target. The binding looks for raylib through `pkg-config` and can fall back to `-lraylib`.

```sh
pkg-config --libs raylib
xgo go .
llgo run .
```

The game opens a 300 by 600 pixel window with a 10-column, 20-row board. Use Left and Right to move. Press Space, Up, or Down to rotate. The program rejects moves and rotations that collide with the board or a locked block. A completed row adds 100 points and shifts the rows above it down. When the next piece cannot spawn, the program displays the score on a Game Over screen.

Read `checkCollision` and `clearLines` first to see how the grid state changes. The main loop uses frame time to drop pieces at 0.2-second intervals and converts grid coordinates to pixels for raylib's drawing functions. The example uses `c.sprintf` to format its score into a C string for `raylib.drawText`.

### Initialize the window

The demo initializes raylib with the dimensions defined by the board constants and requests 60 frames per second.

```xgo
raylib.initWindow SCREENWIDTH, SCREENHEIGHT, c"tetris (powered by raylib and XGo)"
raylib.setTargetFPS 60
```

### Draw the board

Inside the frame loop, the program clears the background and draws the color stored in each grid cell. Subtracting one from the rectangle dimensions leaves a gap between adjacent cells.

```xgo
raylib.beginDrawing
raylib.clearBackground raylib.RAYWHITE
for y := 0; y < BOARD_HEIGHT; y++ {
	for x := 0; x < BOARD_WIDTH; x++ {
		raylib.drawRectangle c.Int(x*BLOCK_SIZE), c.Int(y*BLOCK_SIZE), c.Int(BLOCK_SIZE-1), c.Int(BLOCK_SIZE-1), board[y][x]
	}
}
```

The original `tetris.xgo` also draws the active piece and score before it calls `raylib.endDrawing`.
