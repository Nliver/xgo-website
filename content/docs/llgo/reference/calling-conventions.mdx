---
title: Calling conventions and host-layout structs
description: Declare C and Windows callbacks and preserve native struct layout across the ABI boundary.
---

Use `//llgo:cdecl` for a C callback and `//llgo:stdcall` for a Windows stdcall callback.

```go title="callbacks.go" verify="manual"
//llgo:cdecl
type Handler func(data unsafe.Pointer) c.Int

//llgo:stdcall
type WinProc func(hwnd uintptr, msg uint32, wParam, lParam uintptr) uintptr
```

The older `//llgo:type C` and `//llgo:type stdcall` spellings remain accepted for compatibility and are deprecated. A function type can carry only one calling-convention directive.

A native callback carries one function pointer. Pass a direct function reference and use an explicit context pointer for state. On Windows 386, `stdcall` selects a distinct convention. On Windows amd64 and arm64 it uses the platform’s unified C ABI.

## Mark native struct layout

Use a leading `structs.HostLayout` field when a struct is exchanged with native code.

```go title="host-layout.go" verify="manual"
import "structs"

type Record struct {
    _ structs.HostLayout
    Callback Handler
    Data *byte
}
```

The marker selects native field layout. It does not turn an ordinary Go function field into a native callback. Use an explicitly annotated callback type for that field. Adding the marker changes reflection indexes and positional struct literals.
