编写一个 Go 宿主程序，调用 iXGo 脚本返回的有状态函数。接着用两个解释器上下文运行同一个递归函数，检查宿主如何控制记忆化。使用 Go 1.26 或 1.27，并固定到以下 iXGo 提交。

在空目录中初始化模块。

```sh
go mod init example.com/ixgohost
go get github.com/goplus/ixgo@61dfa28e05d30b5e60b3cfa83b3c79e870cd629e
```

## 调用标准库函数并返回闭包

将以下程序保存为 `main.go`。宿主从字符串加载 Go 脚本，读取解释执行的 `Label` 返回值，再调用脚本返回的 `Counter` 闭包两次。

```go
package main

import (
	"fmt"
	"log"

	"github.com/goplus/ixgo"
	_ "github.com/goplus/ixgo/directcall/strings"
	_ "github.com/goplus/ixgo/pkg/strings"
)

type intFunc struct {
	ixgo.DirectFuncVal
}

func (f intFunc) call(n int) int {
	return f.Call(n).(int)
}

func main() {
	ixgo.RegisterDirectFuncFor(func(value ixgo.DirectFuncVal) func(int) int {
		return intFunc{value}.call
	})

	const script = `package main

import "strings"

func Label() string {
	return strings.TrimSpace("  ready  ")
}

func Counter() func(int) int {
	total := 0
	return func(step int) int {
		total += step
		return total
	}
}

func main() {}
`

	program, err := ixgo.NewContext(0).LoadInterp("script.go", script)
	if err != nil {
		log.Fatal(err)
	}
	label, err := program.RunFunc("Label")
	if err != nil {
		log.Fatal(err)
	}
	callback, err := program.RunFunc("Counter")
	if err != nil {
		log.Fatal(err)
	}
	count := callback.(func(int) int)
	fmt.Println(label)
	fmt.Println(count(2))
	fmt.Println(count(3))
}
```

运行宿主程序。

```sh
go mod tidy
go run .
```

```text
ready
2
5
```

两个空白导入各有用途。`pkg/strings` 注册标准库包的导出信息，让解释执行的代码能导入 `strings`。`directcall/strings` 为 `strings.TrimSpace` 等受支持的操作注册直接调用适配器。如需启用所有随包提供的直接调用适配器，导入 `github.com/goplus/ixgo/directcall`，并注册脚本用到的包的导出信息。`log` 和 `log/slog` 沿用原有调用路径，以便日志能报告调用方的文件名和行号。

`RegisterDirectFuncFor` 将确切的 `func(int) int` 签名绑定到 Go 方法值。在接收者类型中，将 `ixgo.DirectFuncVal` 嵌入为第一个字段。绑定的方法将参数传给解释器并返回结果。应在加载脚本前注册适配器，并在使用该签名的回调仍有效时保留注册。

iXGo 内置 `func()` 适配器。空白导入 `github.com/goplus/ixgo/directfunc` 可以为常见的无参单返回值签名启用适配器，支持 `bool`、整数和浮点类型、`string` 以及 `error`。其他签名和具名函数类型默认通过反射调用，宿主可以按确切类型注册适配器。

## 按解释器上下文控制记忆化

记忆化会缓存结果或受支持的状态变化，供后续调用复用。`ixgo` 命令默认启用相关插件。Go 宿主可以空白导入 `github.com/goplus/ixgo/memo` 启用插件，并在调用 `NewContext` 时传入 `ixgo.DisableMemo`，为该上下文关闭插件。

用以下程序替换 `main.go`，再运行 `go mod tidy` 和 `go run .`。

```go
package main

import (
	"fmt"
	"log"

	"github.com/goplus/ixgo"
	_ "github.com/goplus/ixgo/memo"
)

const script = `package main

func Fib(n int) int {
	if n < 2 {
		return n
	}
	return Fib(n-1) + Fib(n-2)
}

func main() {}
`

func fib(mode ixgo.Mode) int {
	program, err := ixgo.NewContext(mode).LoadInterp("fib.go", script)
	if err != nil {
		log.Fatal(err)
	}
	result, err := program.RunFunc("Fib", 20)
	if err != nil {
		log.Fatal(err)
	}
	return result.(int)
}

func main() {
	fmt.Println("memo enabled:", fib(0))
	fmt.Println("memo disabled:", fib(ixgo.DisableMemo))
}
```

```text
memo enabled: 6765
memo disabled: 6765
```

两个上下文返回同一个斐波那契数。插件先分析递归调用，再决定是否启用缓存。它支持纯标量递归，以及部分使用累加器的递归函数和带接收者的方法。存在外部副作用或不受支持的可变状态时，以及解释器会话启用了跟踪或自定义调用拦截时，代码会走普通解释路径。对适用的浮点运算，插件使用精确的位模式作为缓存依据，保留带符号的零及原有运算顺序。

安装命令行工具及运行首个嵌入式 XGo 脚本的步骤见 [iXGo 解释器](/zh-CN/docs/ixgo)。
