title: 链接本地 C 函数
description: 编译一个 C 源文件，并在 Go 中调用它导出的函数。
---

构建一个调用本地 C 函数的 Go 程序，打印 `42`。你会用 `LLGoFiles` 编译 C 源文件，再用 `//go:linkname` 指定 LLGo 要调用的本机符号。请使用 LLGo `v1.0.10` 和可用的本机工具链。 [安装 LLGo](/zh-CN/docs/llgo/getting-started/installation)

## 创建模块

在空目录中初始化 Go 模块，再创建存放原生源文件的目录。

```sh
go mod init example.com/nativeadd
mkdir _wrap
```

项目包含以下三个文件。

```text
.
├── go.mod
├── main.go
└── _wrap/
    └── add.c
```

将 Go 程序保存为 `main.go`。

```go title="main.go" verify="manual"
package main

import (
	"fmt"
	_ "unsafe"
)

const LLGoFiles = "_wrap/add.c"

//go:linkname add C.add32
func add(a, b int32) int32

func main() {
	fmt.Println(add(19, 23))
}
```

将 C 实现保存为 `_wrap/add.c`。

```c title="_wrap/add.c" verify="manual"
#include <stdint.h>

int32_t add32(int32_t a, int32_t b) {
    return a + b;
}
```

这条没有函数体的 Go 声明指向 `add.c` 中定义的 `add32` 符号。`C.` 前缀指定 C 调用约定。C 函数接收两个 `int32_t` 并返回一个 `int32_t`，因此 Go 声明的参数和返回值都使用 `int32`。这些类型是应用二进制接口（ABI）的一部分，决定两种语言如何在运行时传递数据。Go 的类型检查无法核对 C 函数签名。

## 构建并运行

```sh
llgo build -o hello .
./hello
```

```text
42
```

LLGo 以包目录为基准解析 `LLGoFiles` 中的相对路径。推荐将原生源文件放在 Go 包里的 `_wrap` 子目录中，Go 工具查找包时会跳过这个目录。多个文件用分号分隔。

```go title="main.go" verify="manual"
const LLGoFiles = "_wrap/add.c;_wrap/format.c"
```

## 用 C++ 编译包装代码

将 `main.go` 中 `LLGoFiles` 的值改为 `"_wrap/add.cpp"`。将下面的代码保存为 `_wrap/add.cpp`，沿用前面的 Go 函数声明。

```cpp title="_wrap/add.cpp" verify="manual"
#include <stdint.h>

namespace {
int32_t sum(int32_t a, int32_t b) {
    return a + b;
}
}

extern "C" int32_t add32(int32_t a, int32_t b) {
    return sum(a, b);
}
```

再次运行 `llgo build -o hello .` 和 `./hello`，程序仍会打印 `42`。LLGo 根据文件扩展名选择编译器。C++ 辅助函数仅在该源文件内可见。`extern "C"` 让公开的包装函数使用 `C.add32` 所引用的符号名。

## 添加原生依赖

将编译包装代码所需的选项放在 `LLGoFiles` 的冒号前。如果包装代码调用外部库，请单独提供链接器选项。LLGo 自带的 libffi 绑定用 `LLGoFiles` 指定头文件搜索路径，用 `LLGoPackage` 指定链接选项。 [上游 libffi 配置](https://github.com/xgo-dev/llgo/blob/v1.0.10/runtime/internal/clite/ffi/link_flags_default.go)

```go title="main.go" verify="manual"
const (
	LLGoPackage = "link: $(pkg-config --libs libffi); -lffi"
	LLGoFiles   = "$(pkg-config --cflags libffi): _wrap/libffi.c"
)
```

`LLGoFiles` 的选项段可以使用固定选项，也可以使用受限的 `$(pkg-config ...)` 或 `$(llvm-config ...)` 查询。按上面的 `LLGoPackage` 声明，LLGo 会采用 `pkg-config --libs libffi` 返回的链接选项，未返回选项时则使用 `-lffi`。

## 排查构建问题

- 找不到头文件时，检查包装代码的头文件搜索路径。如果用到了 libffi，可以运行 `pkg-config --cflags libffi`，查看已安装的库提供了哪些编译选项。
- 出现未定义符号时，运行 `llgo build -x -o hello .` 查看构建命令。确认 `LLGoFiles` 列出了定义该符号的文件，C++ 包装函数带有 `extern "C"`，链接命令也包含所需的外部库。
- 架构不匹配时，运行 `llgo env GOOS GOARCH`，将构建目标与所用原生库的架构进行比较。在 macOS 或 Linux 上，可以用 `file` 查看库或可执行文件的架构。
- 如果链接成功但程序返回了意外结果，请对照 Go 声明和本机定义，检查参数位宽、有无符号、返回类型和调用约定。

需要用构建约束选择原生源文件，或绑定指针、结构体、回调和变量时，可以查阅相关参考。 [LLGoFiles](/zh-CN/docs/llgo/native-files) · [调用约定](/zh-CN/docs/llgo/reference/calling-conventions)

如果目标库已经有 Go 包声明了原生调用，可以直接从这个包入手。 [使用 LLGo 绑定](/zh-CN/docs/llgo/tutorials/bindings)
