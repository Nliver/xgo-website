---
title: Use SPX coordinate systems
description: Place sprites correctly by keeping world, asset, render, and screen coordinates at their boundaries.
---

SPX game logic uses a Scratch-style world coordinate system. The stage center is `(0, 0)`, positive `x` points right, and positive `y` points up. Public sprite positions, movement methods, stage bounds, and collision logic use these coordinates.

## Keep coordinate spaces separate

A project can involve several coordinate spaces.

- **World coordinates** describe logical sprite and stage positions.
- **Asset coordinates** describe image pixels, costume anchors, and imported collision paths.
- **Local render coordinates** describe geometry relative to a sprite or costume origin.
- **Canvas coordinates** belong to the rendering backend, where the vertical axis commonly points down.

Convert values when they cross a boundary. Store gameplay state in one canonical space and pass converted values only to the consumer.

## Place a sprite in world coordinates

The following stage script uses world coordinates for both placement and camera setup.

```xgo title="stage.spx"
onStart => {
    Calf.setXYpos 120, 80
    Camera.setXYpos 0, 0
}
```

Do not add a camera offset to `Calf.setXYpos`. The camera changes the view, while the sprite position remains a world position.

## Handle input and collisions

Mouse coordinates exposed by SPX already use stage coordinates. A sprite can use them directly when following the pointer.

```xgo title="pointer.spx"
onStart => {
    forever {
        setXYpos mouseX, mouseY
        wait 0.03
    }
}
```

Collision geometry stays local to the costume or sprite origin. The engine applies the sprite's world translation when it attaches the shape to the physics body.

## Check a coordinate bug

When movement or collisions look offset, check the origin, the direction of the `y` axis, and whether a camera or costume anchor has already been applied. Test a nonzero position with a rotated or asymmetric costume so a duplicated translation is visible.

For image formats and animation assets, see [SPX animation and audio](/docs/spx/animation-audio) and the upstream asset documentation.
